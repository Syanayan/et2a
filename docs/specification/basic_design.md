# 工数管理 VS Code 拡張 基本設計書

## 1. 目的・適用範囲
本書は「工数管理 VS Code 拡張 要求仕様書」に基づき、実装に向けた基本設計（アーキテクチャ、主要コンポーネント、データ設計、API設計、画面設計、運用設計）を定義する。

---

## 2. システム全体構成

### 2.1 構成要素
本拡張機能は以下の論理コンポーネントで構成する。

1. **Extension Host 層（VS Code 拡張本体）**
   - コマンド登録
   - 設定ロード/保存
   - 外部連携 API 受付
   - 予測計算実行

2. **Domain 層（工数計算ドメイン）**
   - 残稼働日数計算
   - バッファ判定
   - トレンド予測
   - アラート判定

3. **Infrastructure 層**
   - `kousu.config.json` 永続化
   - 休暇日同期（API / JSON / CSV）
   - 監査ログ出力

4. **Presentation 層**
   - サイドバー（TreeView）
   - Webview ダッシュボード（バーンダウン / 進捗ゲージ / 警告表示）

### 2.2 依存関係方針
- Presentation → Application(ユースケース) → Domain → Infrastructure の単方向依存を採用する。
- Domain は VS Code API 非依存とし、単体テスト容易性を確保する。

## 3. 機能設計

### 3.1 プロジェクト管理

#### 3.1.1 設定ファイル配置
- ワークスペースルート配下に `kousu.config.json` を配置する。
- 複数プロジェクト管理に備え、`kousu.projects/*.json` を許容する。

#### 3.1.2 複数プロジェクト構成と優先順位
- 読み込み対象の優先順位は以下とする（上位優先）。
  1. ユーザーが UI で明示選択したプロジェクト
  2. `.vscode/settings.json` の `kousu.activeProjectId`
  3. `kousu.config.json`（単一プロジェクト既定）
  4. `kousu.projects/*.json` の先頭（ID昇順）
- 同一 `projectId` が複数ファイルに存在する場合、以下の優先順位で採用する。
  - `kousu.projects/<projectId>.local.json` > `kousu.projects/<projectId>.json` > `kousu.config.json`
- 優先外となった設定は「競合設定」として警告ログに記録し、UI で参照可能とする。

#### 3.1.3 設定ロード/保存
- 拡張起動時、アクティブワークスペースの設定ファイルを読み込む。
- スキーマ検証失敗時は以下のフェイルセーフを実施する。
  1. 最終正常ファイルのバックアップ読み戻し
  2. ユーザー通知（エラー詳細 + 復旧案内）
  3. 破損ファイルを `.broken.<timestamp>` へ退避

### 3.2 工数計算・予測

#### 3.2.1 実績工数更新
- 手動入力（コマンド/フォーム）と外部 API 連携の双方で `effort.actual` を更新可能とする。
- 更新時は監査ログに以下を記録する。
  - 更新時刻（UTC）
  - 更新元（manual / api / sync）
  - 変更前後値

#### 3.2.2 残稼働日数計算ロジック
- 対象期間: `today` から `schedule.endDate` まで。
- `schedule.startDate` は「経過稼働日数」「進捗率母数」「予測トレンド開始点」を揃える基準日として利用する。
- 除外条件:
  - 土曜日・日曜日
  - `schedule.holidays`
  - `members[].personalHolidays`
- 日付比較はタイムゾーン差異回避のため「ローカル日付文字列（YYYY-MM-DD）」基準で実施する。

#### 3.2.3 予測計算ロジック
- 基本式:
  - 平均消費速度 = `actual / 経過稼働日数`
  - 予想総消費工数 = `平均消費速度 × 総稼働日数`
- 枯渇予測日:
  - 残工数を平均消費速度で割り、稼働日カレンダー上で到達日を算出する。
- 表示系は 2 系統を並記する。
  1. バッファ除外ケース（総工数のみ）
  2. バッファ込みケース（総工数 + 外数バッファ、または内数ルールに従う）


#### 3.2.4 予測ロジックのゼロ状態・例外処理
- `actual = 0` または `経過稼働日数 = 0` の場合、平均消費速度は算出せず `insufficient_data` を返す。
- `endDate < today` の場合、予測は「計画期間終了」として固定し、超過工数のみ表示する。
- 残工数が負値（超過）になった場合、枯渇予測日は `today` とし、超過量を別フィールドで表示する。
- 休暇日データ欠損時は「週末のみ除外」の縮退計算に切り替え、警告ステータスを付与する。
- 0除算・NaN・Infinity が発生した場合は計算結果を破棄し、前回正常値を保持する。

#### 3.2.5 警告判定
警告レベルは以下 3 段階とする。

| レベル | 条件 |
|---|---|
| 正常 | 実績工数 < (総工数 - バッファ) かつ 予測消費工数 <= 総工数 |
| 注意 | 実績工数 >= (総工数 - バッファ) かつ 実績工数 <= 総工数 |
| 警告 | 実績工数 > 総工数、または 予測消費工数 > 総工数（外数時は 総工数+バッファ） |

> ※ バッファ内数/外数は `effort.bufferMode`（`inclusive` / `exclusive`）で判定する。

### 3.3 リソース管理
- メンバーは追加・編集・削除を UI から実施する。
- `dailyEffort` は 0.1〜1.5 を許容し、バリデーション逸脱時は保存不可とする。
- メンバー別の将来消化能力を計算し、予測精度向上に利用する（段階導入）。

### 3.4 外部連携

#### 3.4.1 連携方式
VS Code 拡張単体で完結させるため、以下の2方式を提供する。

1. **ローカル HTTP API（任意起動）**
   - `localhost` 限定バインド
   - トークン認証必須
2. **ファイル連携**
   - `import`（JSON/CSV）
   - `export`（進捗サマリ JSON）

#### 3.4.1.1 ローカルAPI 起動/認証運用
- 起動モードは `manual`（コマンド起動）/`auto`（拡張起動時）を選択可能とする。
- 既定は `manual` とし、未使用時の待受ポート開放を防ぐ。
- 認証方式は `Authorization: Bearer <token>` を必須とする。
- トークンは環境変数 `KOUSU_API_TOKEN` から読み込み、未設定時は API を起動しない。
- トークンローテーション時は「現行 + 前世代」の2世代を一定時間（例: 24時間）許容する。
- 認証失敗が連続5回発生した場合、5分間レート制限をかけ監査ログへ記録する。

#### 3.4.2 外部公開 API（案）
- `GET /api/v1/projects/:id/progress`
  - 返却: 進捗率、残工数、予測終了日、警告レベル
- `PATCH /api/v1/projects/:id/effort`
  - 入力: `total`, `buffer`, `actual`
- `POST /api/v1/projects/:id/holidays/sync`
  - 入力: 休暇日ソース定義

#### 3.4.3 休暇日同期仕様
- 同期優先順位: 個人休暇 > 会社休暇 > 週末（除外条件としては同等）
- 重複日は1日として扱う。
- API取得失敗時は前回同期データを利用し、警告トーストを表示する。

## 4. データ設計

### 4.1 設定ファイルスキーマ（基本設計版）
```json
{
  "schemaVersion": "1.0.0",
  "projectId": "p-001",
  "projectName": "新システム開発",
  "schedule": {
    "startDate": "2026-05-01",
    "endDate": "2026-08-31",
    "holidays": [],
    "holidaySources": {
      "company": { "type": "file", "path": "./holidays/company-holidays.json" },
      "member": { "type": "api", "endpoint": "https://example.local/api/member-holidays" }
    }
  },
  "effort": {
    "total": 100,
    "buffer": 15,
    "bufferMode": "exclusive",
    "actual": 45,
    "unit": "person_day"
  },
  "members": [
    { "name": "UserA", "dailyEffort": 1.0, "personalHolidays": [] }
  ],
  "integration": {
    "api": {
      "enabled": false,
      "bind": "127.0.0.1",
      "port": 38100,
      "tokenEnv": "KOUSU_API_TOKEN"
    }
  }
}
```

### 4.2 型定義（TypeScript 想定）
- `ProjectConfig`
- `ScheduleConfig`
- `EffortConfig`
- `MemberConfig`
- `ForecastResult`
- `AlertState`

### 4.3 互換性
- `schemaVersion` によるマイグレーション機構を実装する。
- 不足項目はデフォルト補完（例: `bufferMode=exclusive`）する。

## 5. UI/UX 基本設計

### 5.1 サイドバー
表示項目:
- プロジェクト名
- 進捗率
- 残工数
- 警告レベルバッジ（正常/注意/警告）

操作:
- プロジェクト切替
- 実績工数入力
- ダッシュボード表示

### 5.2 Webview ダッシュボード
コンポーネント:
1. KPIカード（総工数/実績/残工数/予測終了日）
2. バーンダウンチャート
3. バッファ境界線（閾値ライン）
4. 残日数・枯渇予測 2 系統表示
5. 休暇日同期ステータス

### 5.3 通知設計
- `InformationMessage`: 同期成功
- `WarningMessage`: バッファ突入、同期失敗（フォールバック中）
- `ErrorMessage`: 設定破損、保存不可

### 5.4 UI 操作フロー（主要ユースケース）
1. **初期利用フロー**
   - コマンド「Kousu: Initialize Project」を実行
   - テンプレート生成（`kousu.config.json`）
   - 初期値入力（総工数/納期/バッファ）
   - ダッシュボード自動表示
2. **日次更新フロー**
   - サイドバーから対象プロジェクト選択
   - 実績工数入力 → 保存
   - 再計算実行 → 警告判定 → チャート更新
3. **休暇日同期フロー**
   - 「Sync Holidays」実行
   - 同期結果サマリ（追加件数・重複件数・失敗件数）表示
4. **競合解消フロー**
   - 設定競合検知時に詳細パネル表示
   - 優先ファイルの採用/手動マージを選択

## 6. 非機能設計

### 6.1 性能
- 設定ロードは 200ms 以内（通常規模 JSON）を目標とする。
- 予測再計算は入力変更から 100ms 以内に UI 反映する。

### 6.2 可用性・復旧
- 設定保存時に世代バックアップ（例: 最大5世代）を保持する。
- 外部 API 障害時は機能縮退（ローカル計算継続）で運用可能とする。

### 6.3 セキュリティ
- ローカル API は `localhost` のみ公開。
- 認証トークンは環境変数参照とし、設定ファイルへ平文保存しない。
- 監査ログに機微情報（トークン等）を出力しない。

### 6.4 監査ログ
- 出力先: `./.kousu/logs/audit.log`
- 形式: JSON Lines
- 最低記録項目: `timestamp`, `actor`, `action`, `target`, `before`, `after`, `result`

---

## 7. 例外・エラーハンドリング
- 設定検証エラー: 起動時に修復導線を提示し、編集画面を開く。
- 日付不正（`startDate > endDate`）: 保存拒否。
- 工数不正（負数、NaN）: 保存拒否。
- 同期失敗: リトライポリシー（指数バックオフ最大3回）後に警告表示。

---

## 8. テスト観点（基本設計レベル）
1. **単体テスト**
   - 稼働日計算（土日・休暇除外）
   - バッファ内数/外数判定
   - 警告レベル遷移
2. **結合テスト**
   - 設定ロード→計算→UI反映
   - 外部 API 更新→再計算→通知
3. **異常系テスト**
   - 設定破損ファイル
   - 外部 API タイムアウト
   - 休暇データ重複/不正フォーマット
