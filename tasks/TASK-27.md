# TASK-27: 実機 VS Code での動作確認

## 目的

ユニットテスト（フェイク VS Code API）では検証できない実際の VS Code 上での動作を確認し、リリース可能な状態であることを保証する。

## 背景

TASK-22〜26 の実装はすべてフェイク API によるユニットテストで検証済み。実機での描画・イベント連携・ファイル読み書きは未確認のため、拡張機能として実際に動くことを人手で確認する必要がある。

## 作業内容

- VS Code のデバッグ実行（F5）で拡張機能を起動する。
- 以下のシナリオを順に手動実行する。

### シナリオ1: プロジェクト初期化
1. コマンドパレットから `Kousu: Initialize Project` を実行
2. 総工数・納期・バッファ・プロジェクト名を入力
3. `kousu.config.json` がワークスペースに生成されることを確認
4. ダッシュボードパネルが自動で開くことを確認

### シナリオ2: ダッシュボード初期表示
1. VS Code を再起動（既存の `kousu.config.json` がある状態）
2. `Kousu: Open Dashboard` を実行
3. KPI カードに設定値（総工数・実績・残工数）が表示されることを確認（`-` のままでないこと）

### シナリオ3: 実績更新
1. `Kousu: Update Actual Effort` を実行し、数値を入力
2. サイドバーの Progress / Remaining / Alert が更新されることを確認
3. ダッシュボードの KPI・バーンダウンチャートが再描画されることを確認

### シナリオ4: 祝日同期
1. `Kousu: Sync Holidays` を実行
2. 通知メッセージが表示されることを確認
3. `kousu.config.json` の `calendar.holidays` が更新されることを確認

### シナリオ5: 拡張機能の停止
1. デバッグを終了（拡張機能を停止）
2. エラーや警告が出ないことを確認

## DoD（完了条件）

- 5シナリオすべてで期待動作が確認できる。
- コンソールに未処理エラーが出ない。

## 確認チェック

- [ ] シナリオ1: 初期化で `kousu.config.json` が生成され、ダッシュボードが開く
- [ ] シナリオ2: 再起動後にダッシュボードへ初期データが表示される
- [ ] シナリオ3: 実績更新でサイドバーとダッシュボードが即時反映される
- [ ] シナリオ4: 祝日同期で通知と設定更新が行われる
- [ ] シナリオ5: 拡張機能停止時にエラーが出ない
